# fixtures/harness/codex

`fake-app-server.mjs` is a real stdio child that speaks the pinned Codex app-server protocol
(newline-delimited JSON-RPC on stdin/stdout), so the H01 adapter can be exercised end to end without
a real Codex account, network, or desktop session.

Provenance: every method and payload shape used here comes from the JSON Schema bundle generated by
the installed tested CLI:

```sh
codex --version                      # codex-cli 0.154.0
codex app-server generate-json-schema --out <dir>
```

Client → server: `initialize`, `initialized` (notification), `thread/start`, `thread/resume`,
`turn/start`, `turn/interrupt`, and the JSON-RPC response to `item/commandExecution/requestApproval`.
Server → client: `thread/started`, `turn/started`, `item/started`, `item/completed`,
`item/reasoning/summaryTextDelta`, `turn/completed`, plus unknown `future/*` notifications in the
`version-mismatch` scenario.

Scenarios (`H01_SCENARIO`):

- `readonly-task` — streams one read-only command item, one hidden-reasoning delta that must never
  become user-visible content, and one agent message; the first turn ends only when the client sends
  `turn/interrupt`; a later `thread/resume` + `turn/start` streams a second turn.
- `approval` — opens a guarded command item, then blocks on `item/commandExecution/requestApproval`
  (`id` 7) until the client answers; `accept`/`acceptForSession` completes the tool, `decline`/`cancel`
  declines it, and no answer means nothing runs.
- `version-mismatch` — reports `codex-cli/99.0.0`, emits background notifications including unknown
  `future/*` methods, and stays usable for observation only.

Every inbound/outbound message and lifecycle event is appended as JSONL to `H01_JOURNAL`; the
acceptance test reads that journal as wire-level evidence. The child exits on SIGTERM/SIGINT or when
stdin closes, recording a `shutdown` lifecycle entry.
