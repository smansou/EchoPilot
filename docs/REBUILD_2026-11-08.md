# Runtime repairs and workspace rebuild — November 8

User testing exposed failures that synthetic layout checks did not establish. This update treats the prior build as an unsuccessful acceptance candidate.

## Verified runtime changes

- Electron constrains ordinary macOS window frames below the menu bar. A small N-API Cocoa bridge now selectively bypasses frame constraints for the notch panel, sets all-Spaces/full-screen-auxiliary behavior, and preserves normal constraints for unmarked windows. The real native fixture checks top-edge coordinates, visibility above a synthetic full-screen window, and nonfocusability.
- The widget document root is transparent, including its color-scheme. The renderer fixture inspects pixel alpha outside the visible notch. Empty window space is click-through; the visible notch enables pointer interaction.
- Native focused-field lookup now walks the focused element's parent chain before bounded tree search. This reaches text fields hidden deep in large accessibility trees. Permission failures retain a specific actionable message; transcripts remain available after insertion failure.
- Read-only helper status on this Mac reports Accessibility denied. This is still a real prerequisite to verify typing into the user's apps. No permission was granted or bypassed by the implementation.
- Explicit screen requests now prepare the semantic screen map before named target search. The voice session gets the actual backend capability names at startup, a concise delegation policy, and silent delegation acknowledgement. Failed backend work becomes visible in the main window.
- An integration fixture drives voice delegation through screen reading, target lookup, outline selection, and visual explanation. It uses a controlled backend and synthetic screen, and does not establish live speech-model behavior or real desktop access.

## Replacement interface

The prior dashboard implementation is replaced by a dedicated workspace with Home, Work, Conversations, and Settings. Work separates Projects & sessions, Remembered, and Tasks. Settings separates Voice & dictation, Connections, Permissions & privacy, Keyboard shortcuts, and Experimental.

The UX specialist recommended clear primary actions, contextual recovery, readable controls, scoped settings and restrained color, based on Apple's [macOS guidance](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos), [sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars), [settings](https://developer.apple.com/design/human-interface-guidelines/settings), and [privacy](https://developer.apple.com/design/human-interface-guidelines/privacy).

Model selection remains explicit: friendly dropdowns for direct providers, with OpenRouter retaining slug entry. Claude reasoning is adapted through the Messages API; audio continues through the selected voice provider. No paid live-provider calls were made for automated verification.

## Acceptance still required

Grant the packaged app/helper Accessibility access, then verify actual insertion, a live request to read and point to desktop content, and orb behavior on the physical MacBook notch. The branch remains unmerged until these checks succeed with the user.
